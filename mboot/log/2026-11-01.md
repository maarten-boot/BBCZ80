## 99. First real board boot: the firmware crashes before reading the card

* **User:** copied ROSCODE1.BIN to an SD card and booted a real
  rosco_m68k: "no go". Output: "MC68010 CPU @ 10.0MHz with 5242880 bytes
  RAM", "Searching for boot media...", then "*** Software Failure: $Fxxx
  instruction", PC=00E21FB2 op=FFFF (in the ROM), warm boots, one crash
  at PC=006E56F4 with garbage output, at last "No bootable media found",
  "Ready for Kermit receive...".
* **Reading:** "Searching for boot media..." is stage2/main2.c lmain();
  sd_load_kernel() (stage2/sdfat/load.c) prints "SD v1/v2 card:" or
  "SDHC card:" right after BBSD_initialize() succeeds. No such line, and
  no "Loading ...": the crash is in the firmware's SD card start-up,
  before any partition or file is read, so ROSCODE1.BIN is not involved
  (any file would fail the same). An F-line trap on $FFFF in the ROM's
  address range: a jump into an unprogrammed part of the ROM (or a bad
  return address). Suspects: the card (type/size, contacts), the SD
  adapter wiring, or the ROM image itself.
* **Good news:** the firmware reports 5242880 bytes, so the 4 MB
  expansion is contiguous with the board's 1 MB: BASIC will get about
  3.68 MB.
* Asked the user: the banner's firmware version line; the card (size,
  SD/SDHC/SDXC, how formatted); whether this board booted from SD before
  (any ROSCODE1.BIN); try another card (<= 32 GB SDHC, FAT32, MBR).

## 101. Another card: it loads, then the console speed is wrong

* **User:** on another card "it seems to switch to another baud rate,
  initial 38400 works until it loads the software from sd" (the run 14
  artifact, ~/Downloads/bbc68k-rosco); the boot output: banner "Classic
  2.42", "MC68010 CPU @ 10.0MHz with 5242880 bytes RAM", "Initializing
  hard drives... No IDE interface found", then only garbage (the
  "Searching for boot media..." line is not readable either).
* **What BASIC touches** (bare.c bare_init): no CSR, MR or baud command;
  it writes IMR, ACR = $F0 (baud rate set 2, timer, crystal/16), the
  counter (1920: 60 Hz), IVR $45, and starts the counter. Firmware 2.42
  (duart.asm INITDUART): an r2 board (XR68C681) gets extended rates, ACR
  $80, CSR $88 (115200), and then the same ACR $F0 with counter 1152 (100
  Hz) as its tick: there BASIC's writes do not change the speed. An r1
  board (MC68681) gets ACR $60 (set 1, counter) and its 115200 *from the
  counter* (CSR $66): there BASIC's ACR and counter writes would change
  the speed. Neither MAME (null modem socket) nor r68k models baud rates,
  so this cannot show in the emulators.
* **Open:** the board runs at 38400 although 2.42's source sets 115200
  (a custom ROM build, another crystal, or the DUART type?); the garbage
  starts before BASIC can have run (no readable "Searching..."). Asked:
  board revision; whether the terminal shows a prompt at 115200 or another
  speed after the garbage; why 38400.
* **User**, later: the garbage ends in "*** Software Failure: Bus error
  (fault addr 00F006CA)", PC=00480A00, a7=004FFFBE, registers full of
  48024802; after the warm boot "Searching for boot media... SDHC card:"
  is readable again.
* **New reading:** PC $480A00 is neither BASIC (loaded at $40000-$4EB08)
  nor the ROM; a7 is the firmware's stack at the top of 5 MB again. The
  garbage looks like memory printed through a bad pointer more than a
  baud mismatch, and the speed is right again after the warm boot. With
  the first card's crashes (stack at $4FFFxx, returns into blank ROM) the
  common factor is the 4 MB expansion, where the firmware's stack lives.
  BASIC's DUART writes cannot change the speed on an r2 board (its ROM
  probes IDE, so r2): same ACR $F0 as the firmware's tick.
* **memcheck** (rosco code/software/memcheck, release/version-2.42) built

  contiguous and scans. Copied to tmp/memcheck/ROSCODE1.BIN for the board.
