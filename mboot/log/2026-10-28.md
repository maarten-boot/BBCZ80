## 77. Minix: *DIR without /bin/sh?; the log split by day

* **User:** on "68k under Minix: the line goes to /bin/sh": with Minix's
  little memory, avoid short fork/exec's for simple things like ls; is
  it cheap, or should BASIC do it itself?  Then: "The conversation log
  make be geeing a bit long can we split it by day".
* **The answer:** not cheap. Without an MMU, fork copies all of BASIC
  (code, variables, program, stack), then exec needs a second hole for
  /bin/sh, and sh one for ls; on 1 MB the exec already failed with
  ENOMEM (entry 4: about 330 KB free), hence "No room". Only *DIR uses
  the shell (ls -C); the other commands are done in BASIC already.
  Suggested: *DIR in BASIC with opendir/readdir/stat, sharing bare.c's
  pattern code (dirpat, dirmatch, wild) through osl.c; keep the shell
  for unknown commands only. Waiting for the user (Minix is postponed).
* **The log:** split into mboot/log/YYYY-MM-DD.md, one file per day,
  entries unchanged (checked: the same lines); mboot/CONVERSATION_LOG.md
  is now the index. Entries 40-76 had no date: they went under the date
  of the commit that added them.

## 89. Is BBCSDL "mechanical" C? Russell's reply on RESTORE DATA/ERROR

* **User:** could the reference implementations and the EBNF be turned
  into a C implementation (question only)? Answered: the EBNF is syntax
  only, the semantics are in the sources; the tests are the oracle;
  recommended translating our 68k modules one at a time (or Russell's C
  for a portable BASIC).
* **User:** BBC BASIC for SDL 2.0 is, as they understand it, a
  mechanical asm-to-C translation simulating an x86. **Checked**
  (rtrussell/BBCSDL src, bbmain.c, bbexec.c, bbeval.c, 1.43c, about
  8,900 lines; downloaded to the scratchpad only): the structure and
  the names follow the x86 code (esi = program pointer, esp = BASIC's
  stack, ebx/edi/... working pointers; xeq() a switch on the token;
  memory as offsets from zero), but no CPU is simulated: no flags, no
  instructions; native 64-bit integers and double/long double in a VAR
  union, built for ARM, x86-64, wasm and the Pico.
* **Russell's reply** (relayed): RESTORE DATA / RESTORE ERROR with
  nothing to restore is a *difference*, not a bug: leaving a PROC/FN
  restores automatically without an error, so an explicit statement not
  erroring is reasonable. The reverse case: `LOCAL` with no parameters
  is "No such variable" in Z80/68k, no error in Acorn versions.
* **Later** (user: "the rest we will do later"): Z80_DIFFERENCES.md
  section 2 and the d13/d14 REMs still call it a bug ("Still open in
  5.4"); whether 68k keeps its error; LOCAL with no parameters.
