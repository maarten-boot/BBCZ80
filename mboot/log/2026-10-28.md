## 77. Minix: *DIR without /bin/sh?; the log split by day

* **User:** on "68k under Minix: the line goes to /bin/sh": with Minix's
  little memory, avoid short fork/exec's for simple things like ls; is
  it cheap, or should BASIC do it itself?  Then: "The conversation log
  make be geeing a bit long can we split it by day".
* **The answer:** not cheap. Without an MMU, fork copies all of BASIC
  (code, variables, program, stack), then exec needs a second hole for
  /bin/sh, and sh one for ls; on 1 MB the exec already failed with
  ENOMEM (entry 4: about 330 KB free), hence "No room". Only *DIR uses
  the shell (ls -C); the other commands are done in BASIC already.
  Suggested: *DIR in BASIC with opendir/readdir/stat, sharing bare.c's
  pattern code (dirpat, dirmatch, wild) through osl.c; keep the shell
  for unknown commands only. Waiting for the user (Minix is postponed).
* **The log:** split into mboot/log/YYYY-MM-DD.md, one file per day,
  entries unchanged (checked: the same lines); mboot/CONVERSATION_LOG.md
  is now the index. Entries 40-76 had no date: they went under the date
  of the commit that added them.
